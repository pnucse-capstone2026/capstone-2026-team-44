# DemoShop K=20 발표 안내

## 화면 사용

- 상단 **화면 크게**를 누르면 사이드바를 숨기고 본문과 근거 글자를
  확대합니다. 상단의 개요 / 발표 스토리 / 후보 목록으로 계속 이동합니다.
- **발표 스토리**에서 분석 범위, 상위 후보 막대, 대표 후보 두 개를
  차례로 소개합니다. 막대와 카드의 링크는 저장된 후보 상세로 이동합니다.
- 상세의 **처음에는 어떤 차이가 관찰됐나요?**에서 일반 입력과 변경 입력,
  상태 코드, 응답 발췌를 비교합니다. 이어서 **왜 근거가 되나 / 주의할 점**을
  설명하고 기존 추가 검증에 따른 신뢰도 변화를 보여줍니다.
- 기록 ID와 전체 요청은 접힌 기술 정보에서 확인할 수 있습니다. 발췌는
  전체 응답이 아니며 강조 표시는 점수 계산이나 새로운 판정이 아닙니다.

## 1번 요청에 대한 시연 아이디어 (실행 기능 제외)

1. 상위 SQLi 후보 상세를 열고 “같은 입력점 하나만 바꿨을 때 응답이
   어떻게 달라졌는지 보겠습니다”라고 소개합니다.
2. 저장된 일반 응답과 변경 응답을 나란히 보여주고 상태 변화 및 DB 관련
   오류 문구를 짚습니다. “이 오류는 먼저 확인할 근거지만 형 변환 오류도
   비슷한 문구를 낼 수 있으므로 SQLi 확정과는 구별합니다”라고 설명합니다.
3. XSS 후보는 입력 문자열이 응답에 남은 위치와 인코딩 여부를 보여주고,
   “반사는 출발점이고, 브라우저 코드 실행이 확인된 것은 아닙니다”라고
   연결합니다. 해당 신호가 보관된 후보만 골라 설명합니다.
4. 기존 추가 검증 기록과 검증 전→최종 신뢰도로 돌아와 “같은 예산으로
   무엇부터 확인할지 좁히는 것이 이 프로젝트의 기여”라고 마무리합니다.

권장 길이는 후보당 60–90초입니다. 화면 두 장을 미리 캡처해 두면 발표 중
확대 설명에 사용할 수 있습니다. DemoShop의 정답 라벨은 실험 평가용이며
스캐너 관찰 근거나 실제 악용 성공 증거로 제시하지 않습니다. 새 성공 메시지,
수동 재현 엔드포인트와 리포트의 요청 실행 버튼은 이번 구현에 없습니다.

## 새 리포트 생성

저장소 루트에서 다음을 실행합니다. 사용 가능한 loopback 포트가 필요합니다.
러너가 현재 DemoShop을 시작하고 종료하므로 기존 서버의 이전 코드를
분석하지 않습니다. 기존 승인된 Static + focused verification 경로를 사용합니다.

```powershell
python -B tools/results_pack.py --out build/projector-final --port 8901 --top-k 20
```

주 결과는 `build/projector-final/demoshop/dashboard.html`입니다. 단일 HTML로
배포할 수 있고 인터넷·외부 폰트·CDN 없이 열립니다. BAC 결과는 별도
`demoshop-bac/`에 생성됩니다. 각 폴더의 JSON·실행 로그·command.txt와
상위 README가 동일 실행의 근거입니다. 기존 `docs/results/`의 숫자는 이
실행 결과로 간주하지 않습니다. K는 선택된 유형별 후보 수이고, 같은 입력점의
대표 유형만 표시하는 화면에서는 행 수가 K보다 적을 수 있습니다.

## 이번 결과의 검증 범위

2026-09-21 코드 Gate Review는 PASS입니다. 전체 테스트 1,013개 및 최종
변경 후 관련 테스트 42개, 포맷·린트·타입·diff 검사가 통과했습니다.
실제 K=20 결과 파일의 후보 화면 20개와 내부 링크 145개, CSP 해시 및
실증 기능 제외 여부를 확인했습니다. 브라우저 도구의 로컬 파일 URL 정책으로
자동 시각 검증은 수행하지 못했습니다. 발표 전 실제 브라우저와 프로젝터에서
글자 크기, 화면 이동, 응답 발췌의 줄바꿈을 확인해야 합니다.
