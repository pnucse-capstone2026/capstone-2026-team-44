## 한 줄 요약

최종 리포트 대시보드를 비전공자도 따라오는 다중 화면으로 다시 짜고, 시연 타깃 **DemoShop**을 (1) 입력점이 곧 화면 UI인 실제 쇼핑몰, (2) 각 취약 유형 상위 후보 1개씩을 클릭 한 번으로 **실제 취약점임을 눈으로 보여주는** 라이브 검증 화면으로 만들었습니다. 모든 시연 장치는 스캐너가 보는 응답 바깥에 있어 **스캔·채점·메트릭은 그대로**입니다(P@1 1.00 / P@5 1.00 / P@10 0.70 / P@20 0.80).

## 변경 사항

### 1. 리포트 대시보드 (`src/vulnspider/reporting/`)

- 파일 하나 안에서 **분석 개요 / 취약점 후보 / 접근제어(BAC) / 리포트 읽는 법**으로 이동하는 다중 화면. 메뉴·검색·필터·인쇄. 외부 라이브러리·폰트·이미지 없이 오프라인으로 열림.
- 주입 스캔과 별도 BAC 스캔(`--access-control`)을 **한 대시보드로 병합**(`merge_dashboard.py`): BAC 후보를 `ac-` 네임스페이스로 접붙여 id 충돌·링크 깨짐 없이 한 화면에 담고, BAC 스캔이 없으면 안내만 표시.
- 시각 정리: 그라데이션·그림자 제거, 얇은 테두리, 유형색(SQLi/XSS/BAC) 좌측 레일, 히어로("가장 먼저 확인할 곳")에 상위 3 후보.
- 점수는 분석기 값만 표시하고 리포트에서 재계산하지 않음. 용어: **상위 후보 / 최종 신뢰도**(검증이 없으면 검증 전 확률 그대로).

### 2. DemoShop 스토어프론트 (`tools/demo_shop*.py`, `shop.css`, `shop.js`)

- 각 라우트의 canonical GET 폼이 곧 페이지 UI(카탈로그·검색 필터 바, 상품 옵션 패널, 주문 양식 …). 상품 12개로 브랜드·색상·사이즈·정렬·페이지·검색이 실제 동작. 33 엔드포인트 · 100 입력점.
- 크롤 표면 보호: 상품 데이터를 `/assets/products.js`로 분리해 상품·옵션·스타일을 고쳐도 **라우트 HTML(=응답 바이트=랭킹 특징)이 바뀌지 않음**. 스크립트가 없어도 서버 렌더링 상태로 동작.

### 3. 라이브 취약점 검증 + 시연 3개 입력점 (`tools/demo_shop.py`, `decision_html_report.py`)

- **PoC 확인 화면**: `vs_confirm` 마커가 붙은 요청에서만 "취약점이 확인되었습니다" 배너와 증거(계정 전체 유출표 · 타인 주문 조회 · alert 실행)를 응답 맨 위에 표시. 마커 없는 일반 응답 = 스캐너가 보는 것과 **바이트 단위로 동일**(테스트로 고정).
- **대시보드 → DemoShop 연결**: 후보 상세의 "취약점 검증" 버튼이 타깃의 `/_verify`로 이동해 실제 페이로드를 재전송(스토어프론트 입력은 confirm 링크로, 포털 BAC는 세션 쿠키 자동 발급 후 남의 주문으로 진입). `/_verify`는 크롤되지 않음.
- **시연 3개 입력점**(SQLi `/admin/users·q`, XSS `/account/address·city`, BAC `/portal/order·ref`)만 검증 버튼을 노출하고 **각 유형 최상위**로 배치. 표시 전용 순서 보정이라 스캔·메트릭 불변.
- SQLi 화면을 쇼핑몰에 자연스러운 **"아이디·비밀번호 찾기(계정 찾기)"** 로 재구성 — 실제 read-only 인메모리 SQLite 주입(`query_only` + 길이·명령 제한).
- PoC 확인 화면 디자인을 DemoShop 편집형 톤에 맞춰 재설계(상점 팔레트 `var(--ink)/--line/--sand` · 납작한 카드 · 헤어라인 · 절제된 테라코타 강조).

### 4. 시연 다듬기

- 스캐너 관측용 "조회 응답" 더미 카드를 **모든 페이지에서 숨김**(HTML엔 그대로 남겨 스캔 불변, SQLi 유출 증거만 예외). CSS 전용(`shop.css`)이라 라우트 바이트 변화 없음. `입력점 표시`(reveal) 모드는 입력 컨트롤 마커만 표시.
- 회원 로그인·주문 조회 일원화, `/product` 시드/미등록 id → 실제 상품 폴백(플레이스홀더·0원 제거), 로그인 아바타·기본 프로필(한수훈) 정리.

## 리뷰 포인트

- **후보 승격은 표시 전용**(“살짝 tricky”): 시연 3개 입력점을 유형 최상위로 올리는 소수(≤0.1%p) 점수 보정이며 `--verify-links`(DemoShop) 리포트에서만 적용된다. 스캔·채점·메트릭·`RankScore`는 원본 그대로다. `/portal/order`처럼 한 경로에 접근제어 후보가 여러 개면 최고점 하나만 승격한다.
- P@10이 0.80→0.70인 것은 계정 찾기 재구성이 만든 순위 10–11 경계 타이브레이크(수용된 트레이드오프). P@1/P@5는 1.00 유지.
- 형 변환 오류를 흘리는 하드 네거티브 3개(`stock`·`qty`·`min_price`)는 검증도 "근거 뒷받침"으로 판정하는 알려진 한계로 보고서에 기술.
